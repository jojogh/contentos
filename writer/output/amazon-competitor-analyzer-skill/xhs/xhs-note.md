🔥 竞品分析别先看销量，先翻 20 条差评

很多竞品报告，信息很全，结论很轻。

价格、销量、评分、五点描述全列上，会开完还是那句：所以我们要做什么？

问题不在数据不够，在顺序反了。

先看竞品有什么，再猜用户要什么，得到的是一份竞品说明书，不是产品决策。

【换个顺序】

先从评论里找用户在抱怨什么，再回 Listing 看竞品有没有真的解决。

每个痛点都要有评论或 Listing 证据，不能靠常识推断。

【只回答一个问题】

这项痛点，竞品解决到什么程度？

• 已解决得很好：功能、设计、服务都到位，评论里几乎没有负面
• 解决了一半：有方案，但体验有瑕疵、覆盖不全，用户还在抱怨
• 基本没解决：没有方案，或方案效果差，用户反复抱怨

三档对应三个判断：不作为核心方向、体验升级机会、重点未满足需求机会。

【评分不是打分，是走决策树】

1. 竞品有没有明确方案？没有 → 基本没解决
2. 有方案，评论里是否至少有 2 条明确负面？有 → 解决了一半
3. 没有明显负面，再看正面或中性反馈是否到约七成。到了 → 已解决得很好

关键是第三条：不是「没看到差评」就默认过关，要正面证据占主导。

【三张表，对应三个决策】

• 痛点-竞品解决矩阵表：行是痛点，列是竞品方案。读法不是填满，是找空格
• 竞品解决方案拆解表：每个方案写清来源、功能、目标痛点、证据和缺口，解决「为什么没解决」
• 竞品解决方案分析表：按评分从低到高排，直接变成待办清单

【三个边界，先接受再跑】

• 评论每次最多 20 条。它适合发现线索，不适合证明普遍性
• 评分是编辑判断，不是统计结论。不同人看同一批评论，可能给出不同分数
• 「已解决得很好」不等于没机会。功能解决了，表达、服务、配件组合仍可能有空间

【今天就做】

手头有 ASIN 的话，先做一个小动作：

把最近 20 条评论按星级分组 → 只聚类差评和中评里的高频抱怨 → 得到 4-7 个痛点 → 回 Listing 为每个痛点找对应方案 → 找不到就标「基本没解决」

不用跑完整个 Skill，也能在下次选品会前多一个可讨论的判断，而不是又一份参数清单。
