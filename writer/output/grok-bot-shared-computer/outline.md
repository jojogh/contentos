# 提纲

- 骨架：**热点解读**（主）+ 对比决策（第 4 节）
- 读者承诺：读完能确认「Grok Bot 到底怎么隔离」，并据此决定建几个 bot、放什么进去

## 标题方向

选用：**Grok Bot 不是给每个 AI 配台电脑，是给每个账号配一台**
理由：直接指向被普遍误读的前提，正文能百分之百兑现（官方两条原文即可支撑），且能区分于所有同题文章。

## 开头钩子

材料来源：S4（8 月 20 日那篇指南的说法）+ S1（官方文档的反证）。
机制：冲突——一份写得用心的指南，其核心前提与官方文档相反。

## 章节

### 1. 开场：一个被普遍说反的前提
- 服务主张：C1
- 读者问题：我记得不是每个 agent 一台 VM 吗？
- 证据：S4 的表述 vs S1 的两句原文
- 推进：这不是细节，它决定用法

### 2. 官方说的「屏幕」是工位还是隔断
- 服务主张：C2、C3、C4、C6
- 读者问题：那我怎么知道东西会不会串？
- 证据：screen 定义、共享清单、警告原文
- 推进：系统里不存在「只给这一只 bot 看」

### 3. 三个直接后果
- 服务主张：C5、C11
- 读者问题：那我该怎么设计？
- 证据：并发限制 + 共享面
- 推进：并行度上限与权限暴露面积是同一个旋钮（本文核心推论）

### 4. 同一个技术，两种相反的答案
- 服务主张：C7、C8
- 读者问题：别人怎么做的？
- 证据：Muse 的 Sentinel / JIT 凭据 / 独立 VM
- 推进：协调优先 vs 安全优先，没有谁更先进，但要知道自己买的是哪条
- 明确标注：Muse 细节来自二手转述

### 5. 那套「总参谋长 + 专员」还有用吗
- 服务主张：C10、C12
- 读者问题：那篇指南值不值得照抄？
- 证据：指南的组织架构设计
- 推进：方法论没错，顺序反了——在共享文件系统下，先建组织后想权限等于先装修再定承重墙

### 6. 真正值得抄的两个做法（+ 价格口径）
- 服务主张：C10、C9
- 读者问题：那我拿什么去用？
- 证据：Teach-a-Task / Skill File；可逆性矩阵；无独立订阅
- 推进：这两条不依赖具体产品，换任何 agent 都能用

### 7. 反方与边界
- 服务主张：回应任务书中的最强反方
- 证据：共享状态是卖点这一事实
- 推进：收窄到三个不成立的条件

### 8. 结尾：一个更小的第一步
- 行动结尾：列出 /workspace 里的东西，逐条问「另一只 bot 看到会怎样」
- 观察结尾：两个信号（bot 间权限控制是否出现；企业版审批能力是否下放）

## 不做的事

- 不复述发布新闻、不列功能清单、不写「未来可期」
- 不写任何使用体验（未使用过该产品）
- 不给具体价格数字（来源冲突且官方页 403）
