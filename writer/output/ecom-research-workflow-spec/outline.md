# 提纲

## 选定标题方向

主张型主标题 + 明确交付物：**亚马逊选品表数字齐全，结论却站不住：AI 工作流怎么搭**

读者承诺：读完能知道这套工作流由哪两份规范组成、哪类错误会在数据齐全时静默发生、哪些环节不该交给 AI，以及自建时先写什么。

上下文：全文以亚马逊选品为场景——字段模板中的 ASIN、父 ASIN、变体数、FBA 费用、包装尺寸分段、卖家所属地，以及数据出自卖家精灵竞品查询导出，均需在第一节交代。

## 开头钩子

材料来源：U2 开篇的功能定位 + U1 的表结构事实。

用一个具体反差开场——表里 87 列、24 个月逐月数据一应俱全，但会上仍然说不出「能不能做」。直接把读者按到自己经历过的那次会议里，然后给出全文命题：缺的不是数据，是输出契约。前 120–180 字内落到核心判断。

## 主章节

### 一、字段表本身就是工作流的一半（服务 C1、C2）

- 读者问题：模板为什么值得逐列看？
- 证据：五张表；竞品清单 87 列 / 257 行 / 48 个月度列；有效记录数、有效月数、24 月完整商品数
- 交付：字段表不是记录工具，是采集行为的约束条件。带出模板自带的采集纪律——分批 + 复核、父 ASIN 只留月销量最高的子 ASIN。

### 二、需求文档管的不是数据，是「输出契约」（服务 C5）

- 读者问题：为什么字段齐全还是没结论？
- 证据：六部分分析需求；每部分固定三段式（已有 / 仍缺 / 最终要回答什么）；最终输出四列五行
- 交付：把「结论」和「建议方向」拆成两列，是把判断和行动分开的要求。

### 三、数据越全越容易犯的错：分母不一致（服务 C4、C3、C7）

- 读者问题：这张表最可能在哪里骗到我？
- 证据：需求文档原话诊断；257 行中仅 144 行有效月数满 12；价格段合计行的 n.a. 公式与其旁边的「24 月完整商品数」
- 交付：分母换一次，所有比例跟着变。这是全文最实用的一节，也是新增价值所在。

### 四、这套工作流真正交付的四样东西（服务核心判断的「价值」一半）

- 一个统一分母 / 一套可复用的解释话术 / 一张按决策顺序排的表 / 一条能追到字段的证据链
- 每样对应前面哪一步，不空谈价值。

### 五、反方与边界：有一格写着「人工做」（服务 C6、C8）

- 证据：利润核算整张表一句话；第三方估算口径
- 反方：小团队要不要上这套？规范跑不出结果是不是空转？
- 明确不适用场景。

### 六、给出海团队：先写输出契约，再定字段表（CTA）

- 三步顺序 + 一个当天可做的动作（去看自己的采集表有没有「有效记录数」这一列）
- 温和的定位说明：作者在做出海电商 AI 工作流的搭建。

## 结尾

决策/行动结尾：回收「缺的不是数据，是输出契约」，给一个当天可执行动作。
