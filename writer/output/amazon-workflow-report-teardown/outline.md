# 提纲

## 选定标题方向

项目复盘型主标题，用交付物的形态作为钩子：**给客户搭的 Codex 选品工作流，跑完是什么样**（24 字）

（原选「797 条评论，怎么变成 11 条产品需求」21 字，属结果转化型；因本文同时要承担「展示为客户搭建 AI 选品工作流的能力」这一目标，改用项目复盘型。旧标题降为备选第 4 条，适合做二条或转发文案。）

读者承诺：读完能看到一份真实交付物的内部结构，知道这套工作流由哪三块组成、自动化省下的到底是哪部分力气、可信度从哪里来、哪一题它不答。

上下文（须在开头交代）：一次性亚马逊美国站轮胎充气泵（tire inflator）类目调研的交付报告，9 张工作表、80 款竞品、797 条评论、24 个月逐月数据。

## 开头钩子

材料来源：U1 表结构与自述口径。

用"一份类目调研跑完是什么样子"直接摊开交付物规模，再明确全文边界——不评价这个类目本身，只拆自动化的价值落在哪几件事上、以及它明确不做什么。前 120–180 字内落到任务。

## 主章节

### 一、797 条英文评论 → 14 个主题 → 11 条分级需求（服务 C2、C3、C4）

- 读者问题：情感分类到底做到什么颗粒度？
- 证据：星级分桶、14 主题含负面率、四列翻译结构（用户真正想要 / 数据依据 / 产品启示 / 验收标准）、P0–P2 分级、双语与真实购买客户 / Vine 字段
- 交付：**高效**与**便捷**的具体形状；反直觉发现（售后负面率 64.3% 最高，但命中仅 28）

### 二、"准确"的第一层：先把分母说清楚（服务 C5）

- 证据：全表 +38.47% vs 同店 +12.29%；有效记录数 474 → 780；有效商品数 35 → 80；同店中位 +3.45%
- 交付：分母不收口时，数据越全错得越自信

### 三、"准确"的第二层：价格盲区不在便宜的那一端（服务 C6、C7）

- 证据：四段价格带各自的款数 / 单款中位 / 均值中位比 / 带电池占比；「逐问判断」1–6 与需求文档六个必答问题一一对应
- 交付：**增速最快的那一段为什么不是答案**（N=7）；交付物可逐条对照规范检查

### 四、产品开发优势：三条线交叉出来的配置清单（服务 C8、C9、C10）

- 证据：AstroAI 33.0%、销量 CR10 47.6% vs 销售额 CR10 69.5%、腰部 36.3%、长尾堆料无效；评论痛点 × 竞品衰退 × 价格带配置三条线交叉；配置清单与定价锚点
- 交付：产品开发优势的**来源**是可复现的交叉，不是经验直觉

### 五、边界：成本核算那一格写的是「人工做」（服务 C11、C12、C13 + 反方）

- 证据：报告原话「没有成本/毛利数据…间接判断」；利润核算整表一句话；第三方估算口径；小团队不适用
- 交付：自动化的可信度来自「知道哪一题不该答并写下来」

### 六、给出海团队：顺序比内容重要（CTA）

- 先写输出契约 → 再把分母写进表里 → 最后划人工边界
- 温和的定位说明落在结尾
- 当天可执行动作

## 结尾

行动结尾：检查自己的选品表有没有「有效记录数」这类列。
