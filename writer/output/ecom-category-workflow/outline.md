# 提纲

**骨架**：第 7 类「复盘」为主干（目标与约束 → 做了什么 → 结果与证据 → 有效/无效 → 原因 → 下一轮），在第 2、5 节内嵌第 1 类「痛点解法」的分步说明。

**标题方向**：用两个真实数字做锚点（2769 → 1652），承诺「过程 + 工作流形态」，不承诺类目行情结论。

**读者承诺**：读完知道一套可审计的品类研究工作流由哪四层组成，知道自建时先定哪三个判断条件，并且知道这份运行记录哪里不可信。

---

## 开头（120–180 字内进入问题）

钩子类型：**具体问题**。

痛点句「我感觉这个类目能做」无法被复核 → 引出四个必须落表的问题（有效 listing 数 / 谁在卖 / 价格带 / 头部份额）→ 声明材料来源（一份真实运行产物）→ 声明本文不做什么（不复述类目行情）。

**不写**：年代套话、「你有没有想过」、任何未经提供的亲历场景。

## 第一节：先看清楚这个类目里谁在卖

**服务主张**：C2*, C3*, C8。

- 先给结构结论（份额），再给分层表（中位价 / 中位评分）。
- 用份额而非绝对值作为主要表述；绝对值出现处紧邻口径标注。
- 口径声明（C8）放在本节的最后一句，作为读者继续读下去的信任前提。
- 边界：sellerNation 是卖家站点归属 ≠ 品牌国籍。此边界必须紧跟结论，不能挪到文末。

## 第二节：这类结论不是「查」出来的，是「筛」出来的

**服务主张**：C1a–C1e。分步说明工作流四层。

1. 钉死类目边界（node_id_path，为什么用节点而非关键词）
2. 先定分母（2769 → 1652，positive_sales_filter 的作用）
3. 再定分子（depth 配额 20/10/5/14，为什么必须有配额）
4. 留账本（manifest 的三个字段；`provider_pages_exhausted` 的限定意义）

每个步骤都要给「不这么做会怎样」，否则只是流程复述。

## 第三节：1652 行表里能拿去做决策的是结构不是数字

**服务主张**：C4a–C4h（C4h 移至第四节）。

- 长尾结构（240/397、Top10 36.9%）→ 判断：铺货驱动型，非品牌驱动型。
- 低门槛信号（sellers=1 占 90%、评论中位 23、FBA 61.5%）。
- 一个可执行筛法（>$5,000 且 <100 评论 → 192 个），紧跟「这是筛选结果不是推荐清单」。

## 第四节：这套流程真正交付的是什么

**服务主张**：C1–C5 的价值归纳（inference/opinion，不引新事实）。

四件交付物：可复现的分母 / 成本可控的深度预算 / 可直接筛的表 / 可被质疑的证据链。这一节的任务是回答任务书里的「价值」要求——它是从已核实事实中归纳出的价值判断，必须明确不引入任何 ROI 数字或效果承诺。

## 第五节：反方与边界——这套流程会在哪里失效

**服务主张**：C5a–C5d, C6, C4h。

- 未完成状态：manifest 计数 vs 实际文件对不上 → 账本失效 = 表不可审计。
- 脏数据：1 行乱码，证明脏数据静默混入。
- 反方：全部为第三方估算；销售额第一名是 AU 站点卖家（C4h），说明份额大 ≠ 利润优。
- 适用 / 不适用清单。

**位置说明**：反方放在自建建议之前，是因为「能不能自建」的建议必须建立在「这套流程会失效」的认知之上。

## 第六节：如果出海团队要自建，先定这三个判断

**服务主张**：C7a–C7c。

- 先破门槛假设（产物形态本身证明工程部分已可由代理完成）。
- 三个判断：先定分母 / 深度配额化 / 账本必须对上文件。
- C7c 明确标注为作者判断。

## 结尾（行动结尾）

回扣开头「我感觉能做」→ 四件事收束 → 给一个当天可执行的动作：检查自己手上的采集目录 manifest 与实际文件是否对得上。
