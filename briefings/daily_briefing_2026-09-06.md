Claude 用 11 天、60 亿 token,把费马大定理完整形式化成 1300 万行 Lean 4 代码,机器验证通过、零占位符。

别当数学新闻看——这是「无人值守长任务」的一次公开压力测试。对做电商的人意味着三件事:

3. 几十个子 Agent 并行,人类只做架构和评审。内容流水线该抄的是这个组织方式,不是模型本身。

### 草稿 2 · 公众号 · 🛒 AI 电商自动化(hook:实测了 X,结果…)· 已打磨(写作蓝图,待扩写)

**标题(主):淘宝把百亿补贴的数据分析交给了 Agent——跨境卖家照抄这套架构的最小路径**
备选:大促复盘不用人拉数了:淘宝官方数据 Agent 架构拆解

【开头】
大促复盘最磨人的不是分析,是拉数。运营花两天把十几张表拼齐,真正想结论只剩两小时。

淘宝百亿补贴频道把这个环节整个交给了 Agent:取数、归因、出报告,全流程自动。大淘宝技术团队公开了架构细节——不是 demo,是跑在真实大促里的系统。这篇拆给你看,最后给一个 30 分钟能跑通的跨境版最小方案。

【正文分节(每节核心点)】
1. 官方架构拆解:三层各干什么
   - 数据感知层:接交易/补贴/流量数据,定时快照
   - 归因推理层:异常检测 → 多维下钻 → 归因候选排序
   - 报告生成层:结论 + 图表 + 行动建议,直接产出复盘初稿
2. 关键设计:先建指标语义层,再让 Agent 干活
   - 直接让 LLM 查表,口径一乱结论就废
   - 语义层把「GMV、动销率、补贴效率」的定义锁死,Agent 只做取数和推理
   - 整套系统里最值得抄的就是这一层
3. 平移到跨境店铺:30 分钟最小路径
   - 把 ERP/广告后台的 10 个核心指标写成一张语义表(名称/口径/取数 SQL)
   -  Claude + MCP 接数据源,只开读权限
   - 固定 3 个高频问题(日复盘/异常归因/周报)先跑两周
4. 边界:它答不了什么
   - 口径没定义过的问题答不了——语义层覆盖决定上限
   - 归因结论要人复核,尤其涉及预算调整
   - 数据权限和合规红线由人把守

【结尾】
工具会换,「先把口径定义清楚再谈自动化」这件事不会过时。

4. 用纪实摄影风格破掉 3D 渲染感
